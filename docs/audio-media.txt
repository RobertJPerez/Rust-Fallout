# Audio source preparation

## Implemented producer slice

The source51 basis had no audio preparation module. This slice adds a
source-qualified WAVE producer in `fallout-data`: it asks the existing `MountIndex`
for one unambiguous archive member, validates its `AssetSource` against the selected
`ArchiveInput`, and extracts it through `ResourceJobs`. The returned `PreparedSound`
owns the existing `Artifact`; its source archive and aggregate decoded-byte
reservation remain pinned until the sound is dropped.

The decoder accepts only RIFF/WAVE with the classic integer PCM format tag,
mono or stereo channels, and 8- or 16-bit samples. It checks RIFF/chunk extents,
odd-byte padding, format chunk size, nonzero channels/rate, bytes-per-second,
block alignment and complete frames before exposing the sound. Unsupported
containers, format tags, channels, sample depths, extensions and duplicate data
chunks fail with an error. File extensions do not select or validate a codec.

PCM is returned as interleaved normalized samples in bounded frame chunks. The
source sample rate and channel layout are preserved; this producer does not mix,
resample, apply gain, or claim a device clock. `PcmStream` checks its caller-owned
`JobToken` before work, every 256 frames, and before publishing each chunk. Dropping
the stream does not release the retained source; dropping `PreparedSound` releases
the `ResourceJobs` artifact and budget pin.

The existing archive cap is 256 MiB per member; `ResourceJobs` also charges each
pending/retained artifact to its configured aggregate decoded-byte budget. PCM
pulls are capped at 4096 frames. These engineering bounds limit memory and
cancellation latency; they are not measured original-game duration or playback
rules.

## Scene-host request adapter

The preview host admits prepared PCM sounds through a nonblocking `sync_channel`
with a default capacity of eight queued requests and one worker processing at most
one request at a time. The single worker decodes and hands off one bounded PCM
chunk at a time. Requests carry the current `Loading.epoch`; advancing the epoch
cancels active and queued requests from the previous scene. Each handle exposes a
sticky success or error result and can cancel only its own request. Scene systems
poll results rather than waiting on the worker.

The audio-04 draft adds a Bevy/Rodio sink that feeds one bounded four-chunk PCM
queue to a custom source and samples `AudioSinkPlayback.position()` as its observable
source clock. It reports decoder, queue and startup failures through the request
handle. The worker completes after Bevy reports the source sink empty; this is not
proof that physical device buffers drained or that audio was audible. The focused
decoder tests use generated samples and do not open an output device. The production
host still needs to register this plugin with the approved Bevy Audio feature, and
presentation still needs to select and submit dialogue cues. Those integration
steps are not claimed here.

The audio-03 music interface reuses the same finite request queue and worker. It
accepts source-frame seeks through a per-track queue capped at eight commands; each
accepted seek invalidates the previous stream token before decoding from the new
frame. Stop cancels that track's active token. Success is reported only when the
bounded PCM stream reaches natural end and the sink finishes; decoder and sink
errors remain separate failures. The worker does not loop a track, and each PCM
pull stays within the existing 4096-frame maximum. The prepared archive member and
its `ResourceJobs` budget lease remain pinned for that finite request. This
interface still accepts only the existing PCM WAVE subset; it does not decode
music MP3/Ogg or choose a music cue.

## Deliberate open work

`actors::voices` records that effective actor voice and audio-path selection are
unsupported. `world::conversation` retains the source `Sound` form link, but does
not identify a localized filename. These layers do not infer a dialogue cue, select
language, resolve localization, parse LIP or schedule voice/music/radio. Synthetic
sink and decoder tests cover queue and PCM stream mechanics; they do not establish
original audio fidelity, device playback, dialogue selection/subtitle timing or
source music-cue behavior.

The WAVE subset follows Microsoft's `WAVEFORMATEX` fields and PCM constraints:
<https://learn.microsoft.com/en-us/windows/win32/api/mmreg/ns-mmreg-waveformatex>
and its RIFF/WAVE chunk description:
<https://learn.microsoft.com/en-us/windows/win32/xaudio2/resource-interchange-file-format--riff->.
No external decoder implementation or retail asset is copied into this repository.

The original-media cue audit found no checked-in menu or authored-sequence cue
mapping. The existing source request accepts an unambiguous archive member; it
does not mount loose media files. A local read-only installation inventory found
loose MP3 media, including a `Music/Special/MainTitle.mp3` candidate, but the
filename alone does not establish that a current route selects it. MP3 is outside
the admitted WAVE subset. Do not infer a route cue or treat the candidate as
playable. Audio-08 remains open until the host supplies an explicit source cue
and source-selection policy, and the required format has a bounded consumer.

## Synthetic verification

`fallout-data/tests/audio_source.rs` builds a one-member BSA104 fixture in memory
and exercises VFS uniqueness, source identity, artifact lifetime, bounded PCM chunks,
per-stream cancellation, truncated format data, zero channels/rate, oversized
declared payload and explicit unsupported ADPCM. These cases verify engineering
behavior only; no original-game audio corpus or device playback is claimed.
