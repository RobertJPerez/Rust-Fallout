# Engine acceptance

The tools/engine-acceptance/scene_replay.py script runs and compares fixed
interior preview captures. It records the assigned source revision and relevant
source file hashes, preview binary hash, scenario and load-order hashes, ordered
plugin hashes from the scene report, requested camera inputs, source origin,
placement transforms, model and texture digests, residency identities, and PNG
pixels.

The source fingerprint is a sorted inventory of files under crates/ and tools/,
plus Cargo.toml, Cargo.lock, rust-toolchain.toml, and any .cargo configuration.
It covers newly added modules, local crate sources, shaders, and build inputs,
so a changed or added transitive source file changes the pin. Cargo path
dependencies and Rust path/include references outside these roots are refused.
The inventory is capped at 4096 files, 64 MiB per file, and 256 MiB total. The
workspace-level local evidence directory is outside the inventory roots, while
nested source directories named local remain covered. VCS/build/cache directories
and Python bytecode are excluded.

The harness uses the existing preview command with explicit source-space camera
position and target, headless 1280 by 900 output, and a separate report and PNG
for each required scenario. It creates a new evidence directory and never
replaces a report or capture. A run is complete only when every required
scenario exits successfully and produces fresh report and image files. An
all-skipped or partially completed matrix cannot pass.
Failed runs retain hashes and timestamps for any fresh report, image, or log
that was produced, while remaining failed and ineligible for replay acceptance.
Completed resource jobs do not prove complete placement coverage: jobs cover the
source-derived requests, while the separate coverage flags account for unresolved
model and texture references.

The scenario input is a private JSON file. Its schema is:

    {
      "schema_version": 1,
      "cell_editor_id": "GSDocMitchellHouse",
      "viewport": {"width": 1280, "height": 900},
      "runs": [
        {
          "id": "view-a",
          "required": true,
          "camera": {
            "source_position": [2130, 2130, 7440],
            "source_target": [1883, 1763, 7420]
          },
          "image_tolerance": {
            "max_channel_delta": 0,
            "max_changed_pixels": 0
          }
        }
      ]
    }

Camera values are engineering inspection inputs. They are not retail defaults
or a matched original-game capture. Image tolerances must be set before a run
and remain part of the pinned scenario file.

Use a unique destination under local/v4-evidence. Keep the scenario file and all
outputs private because captures contain retail assets. Build the preview
through the shared slot wrapper, then run capture and comparison through the
heavy slot wrapper:

    python tools/team-build.py --lane engine-acceptance --session <lease-uuid> -- cargo build -p fallout-preview
    python tools/team-build.py --lane engine-acceptance --session <lease-uuid> --slot heavy -- python tools/engine-acceptance/scene_replay.py capture --repo . --binary target-v4/debug/fallout-preview.exe --install 'G:\SteamLibrary\steamapps\common\Fallout New Vegas' --load-order <private-load-order.json> --config <private-scenarios.json> --output-dir local/v4-evidence/engine-acceptance-01/<unique-run-id>
    python tools/team-build.py --lane engine-acceptance --session <lease-uuid> --slot heavy -- python tools/engine-acceptance/scene_replay.py verify --expected local/v4-evidence/engine-acceptance-01/<frozen-run>/manifest.json --actual local/v4-evidence/engine-acceptance-01/<new-run>/manifest.json

A capture manifest is a candidate frozen engineering baseline. Verification
passes only when the current source, binary, inputs, camera request, placement
poses, resource manifest, and pixels match that candidate. A changed pose or
missing model/texture resource fails the frozen assertion. This tests replay
stability; it does not validate retail behavior.

Verification bounds each JSON input to 64 MiB, rejects malformed scenario and
resource rows with structured acceptance errors, and validates integer fields
without accepting JSON booleans as numbers. Frozen JSON values are compared by
type as well as value. Empty logs are valid artifacts when their path, size,
digest, timestamp, and run interval all match the manifest.

Observation states remain explicit. The current host provides a PNG, source
placement transforms, input camera coordinates, and model/texture/residency
reports. It does not report the applied camera transform or a scene-completion
receipt. Verification now refuses a comparison when either receipt is absent,
mismatched to the source root or generation, or inconsistent with the requested
camera and scene counts. A canonical player body pose, per-frame readiness, and
post-exit resource drain remain absent. The preview also explicitly reports
that simulation readiness and retail parity are false.

The Python stdlib test suite exercises exact image comparison, tolerance
handling, stale capture rejection, aggregate/per-run completion, source-root
and generation pins, expected reference membership, camera receipt freshness,
missing scene-completion refusal, and negative missing-resource and changed-pose
mutations:

    python tools/engine-acceptance/test_scene_replay.py

An omitted placement is not evidence that the original game hides it. In this
static adapter, `no-supported-modl` means the resolved base record did not yield
a non-empty `MODL` path; alternate runtime model selection remains deferred.
Actor model selection is a separate unimplemented path. `initially-disabled`
records are skipped by the non-canonical inspection path. Preserve these rows
and the incomplete coverage flags instead of counting them as rendered or
dropping them from the report.

## Protected scene membership gate

Scene evidence retains the source residency root and generation, plus a digest
and count for the complete placement-key set. The frozen expected manifest pins
that set; the current capture must match it exactly. Every expected placement
must have a rendered draw and an observed model resource. Missing, disabled, or
unsupported rows remain in the expected set and cause refusal; the acceptance
tool does not infer an exception from their status.

The protected scene review records 435 source placement keys and 400 rendered
references. That report is diagnostic evidence for a coverage gap, not a passing
scene. A capture or comparison must refuse incomplete membership, missing draw
or resource rows, and absent aggregate completion data. Camera and completion
receipts must bind the same scene root and current generation. The camera receipt
must also bind the requested position and target before its applied transform is
compared. These checks consume private source receipts and digests; raw game
reference data stays in private evidence files.

## Movement acceptance gate

The current movement pieces expose separate proposals. Actor package route
endpoints identify a cell and NAVM triangle; they carry no exact point or
admitted actor body profile. The local-motion producer needs exact start and
goal points plus an explicit planar footprint radius, and marks every emitted
segment as requiring a collision sweep. A caller-supplied radius is an input,
not evidence that an actor body profile was admitted.

The physics sweep returns an immutable proposal for its explicitly supported
zero-tagged frozen sphere-core profile. The resident `CellCollision` owner
currently exposes ray and overlap queries, reports collision readiness as
unsupported, and has no sweep entry point. The CLI sweep consumes an offline
collision source and an explicit request file; its report does not move an
actor. The actor package candidate likewise reports movement and execution as
unsupported, leaves state unchanged, and refuses execution.

Acceptance-03 remains open until a tested scene consumer joins the actor's
source-qualified route, exact endpoint positions, an admitted body footprint,
and a sweep against the active collision scene and source epoch. It must
validate the proposal against the current actor revision before committing a
canonical pose. Camera transform observations stay independent from that pose.
Then run the assigned wall, step, doorway, frame-rate, and cold-restore cases;
verify blocked motion preserves pose and camera-only changes preserve pose.
Producer tests and offline sweep reports do not satisfy these scene cases.
