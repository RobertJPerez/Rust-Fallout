Application host

The application Host owns the existing canonical World. Source content stays
immutable; inventory, references, events and native captures use runtime APIs.
No second world, item bank or save representation is introduced.

For the supported whole-lot transfer, select_transfer qualifies both registered
owners against winning placed-reference headers and validates the item's source
roles through the supplied explicit Policy. The returned private Selection binds
host identity, scene generation, campaign, content fingerprint, canonical revision,
item handle, complete quantity and source keys. Dropping it has no effects.

Selection::command takes the caller's nonzero request identity. Host::transfer
admits the existing bounded inventory stage and reserves receipt retention before
committing once. Identical accepted retries return the same immutable receipt;
reusing the identity with another selection refuses. Revision, source, quantity,
bank initialization, scene, host and capacity refusals preserve canonical state.
Receipts are retained without eviction until the host is dropped or publishes an
admitted Continue. A full ledger
refuses new requests while existing same-scene retries remain available.

advance_scene cancels prior scene selections without changing canonical state.
Host identities and item handles expire across fresh restore. They are transient
input guards, not a new durable request format. A saved inventory still comes from
the canonical World and the existing SaveWorker.

The first operation transfers an exact complete lot. Partial quantity, inferred
inventory initialization, dynamic owners without source identity, equipment/crime
rules and original activation scripts are unsupported. This is an explicit host
command; it does not infer retail action semantics from source headers.

Save captures Host::world through the existing Captured::at_boundary and SaveWorker.
Continue uses the existing RestoreTask, RequestIdentity and RestoredCandidate.
begin_continue binds the active host, scene, revision, campaign and source cohort;
request identities advance within the host. Cancellation and supersession affect
only that transient request. The task owner keeps it alive until the candidate is
accepted. prepare_continue takes the native result into an opaque private candidate;
it does not replace the active canonical World.

publish_continue rechecks the current request and canonical boundary. Its borrowed
ScenePublisher prepares the complete destination: current display stamp, every
active source member, resource readiness and all fallible draw conversions. The
scene producer must retain its residency owner and immutable membership through
this synchronous call. ScenePublisher::prepare is the final fallible operation;
publish consumes the owned renderer stage infallibly, without another lookup,
membership check or asynchronous write. The application replaces its World only
after preparation succeeds. The receipt carries prior and candidate host identities,
scene generation and revisions so the display can adopt the exact canonical result.
This boundary does not authorize a different thread to publish later.

An accepted Continue gives the host a new process-local identity and clears its
transient transfer ledger. Numeric saved revisions may repeat or move backwards;
TransferResult acknowledgements must match host identity and scene generation as
well as their transaction revision. Old selections cannot execute or replay in
the restored host, including when the revision is identical. Failed scene or
canonical admission preserves the complete active World and displayed state.

application_inventory and application_continue consume the public runtime API
with independently authored plugin headers and complete snapshot comparisons.
The latter uses SaveWorker and a fresh child process to restore exact inventory,
quest-owned script locals and pending events. This does not establish original
quest-stage semantics. The scene fixture is not the native renderer or GPU proof.
Visible input, original menus, the legacy native-host failure reproduction and
independent frozen route acceptance remain required consumer work. These adapters
are dependency slices until the real scene host consumes them.
