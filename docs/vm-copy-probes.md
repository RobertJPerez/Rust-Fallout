# Standalone replacement copy observations

`fallout script-trace --replacement-copy <request.json>` runs the replacement
half of a bounded own-local engineering probe. It uses the existing prepared
source, local-copy adapter, opaque staged changes and canonical commit API.
`--replacement-trace` and `--replacement-copy` are mutually exclusive.

```powershell
fallout script-trace --install <private-source-copy> --load-order <order.json> `
  --manifest <manifest.json> --profile-receipt <profile-receipt.json> `
  --replacement-copy <copy-request.json> --output <report.json>
```

The request has schema version 1, a nonzero canonical `campaign` byte array, a
nonzero `activation`, and `initializers` containing an `index` and canonical
`value`. For example, `{"kind":"number","bits":9223372036854775808}` is the
exact binary64 negative-zero word. These integers are parsed as `u64`, without a
floating JSON intermediary. Only explicit finite Number initializers are
admitted; duplicates, nonnumeric values, NaNs and infinities are refused. No
unassigned slot receives a guessed default. Request limits are 64 manifest steps
and 128 initializers; the CLI also bounds the request to 4 MiB.

Every step must name the same explicit fragment activation, default empty caller
roles and an assignment copy. The existing adapter requires one own-local read
and one own-local destination inside Begin/Assignment/End. The actual source
instruction and observed operand bits must agree with the manifest. Conversion,
branch, native and external-caller execution remain unsupported.

Each producer step executes one complete event and therefore requires distinct
consecutive `event_ordinal` values starting at zero. A duplicate ordinal is
unsupported before preview or result commits; skipped/reversed ordinals fail
manifest validation. Imported traces can still contain multiple observations
within one event. That broader trace format does not authorize this producer to
replay a grouped observation as another event.

A private preview uses the same staging/commit API to check the complete input
sequence. That preview world is discarded. Only a fully supported preview
permits the requested private result world to commit source copies. Unsupported
scope or differing actual operand bits returns an incomplete capture with no
committed result effects and equal initial/final snapshots. Resource/source
errors refuse the request instead of returning a partial successful result. The
runner never receives or mutates a caller's live campaign.

The report includes `replacement_observation`, its ordered actual capture,
canonical commit receipts and the existing initial/final `Snapshot` objects.
`canonical_restore_verified` records a same-process restore and exact snapshot
comparison; it is not a fresh-process Continue or gameplay proof. Capture words
retain exact hexadecimal bits, and the producer's actual CLI executable bytes
and copy-request bytes supply the producer and transport-receipt digests.

An absent original capture still produces a blocked comparison and nonzero CLI
exit, even when the engineering copies ran successfully. The replacement
artifact remains available in the report for later comparison. No original
expectation is generated by this producer. `faithful_execution_admitted`,
`retail_execution_performed` and gameplay acceptance remain false. A supplied
profile receipt does not authenticate original capture transport or prove
original process isolation.
