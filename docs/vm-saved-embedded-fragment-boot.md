# Saved embedded fragment activation

V3-VM-35 creates one explicit engineering Fragment activation for one exact
embedded unit in an existing current-schema campaign. It reuses
`attachment_boot::prepare_input`, `prepare_definition` and `initialize`, the
existing cached source compiler, and canonical `World::create_instance/assign`.
It creates no event or reference and executes no script. No parser, dependency,
save schema, automatic activation, owner default or Original trigger rule is added.

`fragment_boot::prepare(&PreparedSources, &Content, Selection, &Request, Limits)`
returns Unsupported or a borrowed private BootPlan. Request and BootResult alias
the existing attachment boot types. Selection supplies the exact Handle, a
nonzero activation and explicit intent. Faithful reports unverified Original
activation/initialization/trigger semantics before effects. Engineering requires
the exact current record key/SCHR offset/version, compiler-admitted cached unit,
non-Standalone physical owner and nondeleted containing source form. The source
OwnerKind and schema_ownership_verified are reported with their existing certainty;
they establish no dialogue or stage execution semantics.

Five existing input caps bound initializers, context arguments, variable strings,
source receipt payload and declarations. A sixth cap bounds conservative selected
input/source name copies. Before normalization or result copies, admission reserves
`6 * input_variable_bytes + 8 * actual_handle_strings + 4 * version_strings +
cohort_bytes + decoder_bytes + 256`. Caller handle strings participate in the
input counter. Remaining global capacity restricts the existing input preflight.
These are logical payload bounds, not peak heap or wall-clock measurements.

BootPlan borrows immutable source and caller input. Consuming a supplied snapshot
into a private restored World checks the campaign and source cohort, refuses an
existing Fragment activation and uses the shared initializer. Any late context,
storage, allocator, revision or canonical capacity failure discards the private
result. A successful result retains unspecified slots as Uninitialized and preserves
all existing owners, references, inventory, pose, contexts, journal and clocks.

The additive flag is `--fragment-boot-request`, with the existing required
`--snapshot-input/--snapshot-output` and optional report output. Its strict schema-1
DTO is at most 512 KiB and accepts only string intents `faithful` or
`engineering_fragment_activation`. Exact definition/activation/initialization,
the existing source/preflight and initializer limits, retained-name capacity, four
preparation caps and trace/result/report caps are required. Caller/containing/target
fields must explicitly contain a nullable value. Duplicate/unknown/missing fields,
raised ceilings and output aliases are refused through the existing helpers.

The existing source diagnostic preflight bounds source bytes, names and indexed
headers; it performs no REFR attachment join and grants no authority. Catalogue,
Content and only the exact selected source cache are loaded under bounded limits.
Source diagnostics borrow immutable receipts; trace encoding is bounded before
restoration. Complete encoded result, cold equality and bounded typed report
admission precede fresh result publication. Report/result writes are separate
filesystem actions, not a crash-atomic transaction.

distinct declarations, reference tables and exact versions. Each selected unit
has three declaration slots; two explicit initializers leave one Uninitialized.
