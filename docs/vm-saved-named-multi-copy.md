# Explicit complete copy event for a saved named owner

`copy_probe::stage_pending_multi_owned` names an existing journal head and its
exact current Quest or Placed owner. It reserves the explicit Quest plugin name
within the existing observation variable budget before canonical validation or
comparison, then delegates to `World::stage_source_multi_copy_with_sources`.
The consuming `commit_pending_multi_owned` wrapper uses the same opaque stage
and canonical commit. Fragment owners use their existing separate interfaces.
No owner, attachment, reference, initial local or event is manufactured here.

The unchanged adapter evaluates supported own numeric bit copies in physical
source order with its private overlay. Repeated destinations produce only their
final values in one canonical transaction, one revision and one head
acknowledgment. Unsupported later statements discard the whole overlay. Opaque
stages retain the existing source, campaign, world epoch, revision and exact
event guards. Faithful intent remains an unverified-semantics refusal.

The additive CLI mode is `event-operands --snapshot-multi-copy-request REQUEST
--snapshot-input BEFORE --snapshot-output AFTER --output REPORT`. Its strict
schema-1 request requires sequence, explicit named owner, string intent,
`maximum_source_instructions`, `maximum_statements`, `maximum_operand_uses`,
`maximum_statement_bytes`, the four `maximum_trace_{source_bytes,rows,
variable_bytes,binding_uses}` bounds, `maximum_trace_bytes`,
`maximum_result_snapshot_bytes` and `maximum_report_bytes`. It reuses existing
MultiLimits ceilings, with 16 KiB requests, 1..2 MiB encoded trace, 1..64 MiB
result and 1..8 MiB complete pretty report plus newline. Bounds can reduce these
ceilings. The explicit owner reservation is separate from the actual frame's
variable-byte counts. Borrowed selected-definition metadata is checked before
its handle is cloned into the existing source cache.

The CLI restores the strict current snapshot, prepares only the existing head's
exact definition and admits the borrowed encoded trace before committing its
private world. It verifies complete result encoding and cold decode/restore
equality, then admits the complete typed report before creating an output. Result
and report are distinct fresh artifacts outside the installation; existing files
and aliases refuse. A semantic refusal emits a report with no committed trace or
result snapshot. Input, identity, source and capacity errors create neither
artifact. An I/O failure can leave an incomplete fresh artifact; this does not
claim crash-atomic multi-file publication.

Authored probes independently derive A->B, B->C, D->B, B->A: copied words are
A,A,D,D; final A=D, B=D, C=A. Quest and Placed instances share one definition and
indices while retaining distinct values and contexts. Literal whole snapshots
include clocks, unrelated owners, a disabled placed reference, signed-zero and
subnormal pose, inventory19, NaN condition, opaque extras and the unchanged queue
suffix. Fresh processes cold restore that event's result, execute three existing
Fragment events through the cooperative prefix job and consume the later other
named owner. These are separate complete operations. Evidence remains scoped
engineering verification; original read-after-write behavior, assignment
conversions, scheduling, physical interaction and gameplay are unverified.
