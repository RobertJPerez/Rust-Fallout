# Winning conversation source requests

`world::conversation::DialogueSources` connects the existing membership index,
narrative decoder, condition owner preparation and loaded script definitions.
Build it once from the protected `RecordStore`. `topic_infos(topic)` is the
existing canonical-key sorted structural membership list. The caller explicitly
chooses a topic and INFO; this list does not establish retail response selection.

`request(topic, info, speaker)` seals complete ordered source receipts. An optional
speaker is an explicit caller-supplied actor identity, not a default or evaluated
dialogue speaker. `prepare(store, request, signatures, limits)` refuses a changed
source cohort, moved/deleted INFO, deleted topic or wrong-kind speaker. It reads
the exact winning DIAL and INFO through the existing strict bounded store.

The CLI exposes the same producer as `conversation-sources --install INSTALL
--load-order ORDER.json --topic Base.esm:100 --info Base.esm:300`. Keys use original
plugin-local identity, rather than a runtime load-order byte. Optional `--speaker`
supplies explicit actor identity and `--bind-result-fragments` verifies the
existing loaded script catalogue's exact units. This reports hashes and source
metadata without emitting raw story text. The inspector supplies no native
condition signature table; unsupported functions remain explicit. Existing
`dialogue-membership` behavior remains the structural index inspection.

The CLI also consumes every response-owned NAM1 span through the retained
`info_bytes` accessor. `subtitle_payloads` carries its response ordinal, original
response number, occurrence ordinal, exact INFO field index, byte length and
SHA-256. Repeated occurrences, original terminators and non-UTF8 bytes remain
distinct; orphan fields remain in source metadata rather than being assigned to
a response. A hash mismatch refuses the report. Indexed field access visits each
response-owned field once, without rereading the plugin or repeatedly searching
for the next occurrence. These receipts contain hashes rather than story text;
they establish source-byte consumption without admitting UI display, voice
playback, dialogue eligibility or original timing.

The returned `ConversationSources` retains their original decoded bodies and
checked field spans. Presentation can consume `subtitle_bytes(response, occurrence)`
directly, including original terminators and non-UTF8 bytes. Repeated NAM1 fields
remain distinct and response numbers do not reorder authored sections. Orphan
text remains in the original field table with its finding; it is never silently
assigned to a response. `topic_bytes(index)` exposes an original FULL/EDID or
other explicitly indexed field without substituting authored interface text.
Response preparation indexes physical field ownership and TRDT markers in one
pass over the existing bounded decoder output. Fragment role counts use a small
temporary section-kind index. Neither operation rescans all source fields/units
for each response/fragment; authored order, repeated response numbers, orphan
fields and duplicate-role refusals remain the same. These indexes are private
temporary storage under the existing field/section ceilings, without new metadata
or save formats. Maximum admitted field/section consumer fixtures compare exact
metadata hashes and original subtitle spans; timing samples are diagnostics,
with no machine-dependent performance threshold.

`metadata().conditions` is the existing `PreparedOwnerRecord`, preserving exact
CTDA bytes, original physical owners and bound operands. Its sites can feed the
scripts condition request API. Missing signatures, unknown truth, default subjects
and executable grouping remain unavailable until the scripts consumer supplies
verified semantics and explicit context. The conversation request's receipt hash
is its own sealing domain; it is not the runtime catalogue/execution digest.

`metadata().fragments` contains source-bound `ScriptKey` requests for authored
begin/end markers. `resolve(catalogue)` verifies immutable loaded-unit provenance,
record body, script metadata, compiled extent/hash and schema owner before yielding
the existing `LoadedScript` borrow. Repeated or unknown roles refuse. This resolves
one exact source unit; full runtime cohort admission and execution timing remain
separate requirements owned by scripts. Public mutable catalogue reports cannot
confer that authority.

INFO and DIAL form links use the winning source's own master namespace. Metadata
retains raw IDs, canonical keys, full source digests and defined/deleted/missing/null/
runtime-dependency states, including response TRDT sound IDs. A SOUN link is not a
verified dialogue voice filename or playback request. No autogenerated voice naming,
archive winner, silent dialogue substitution or fragment invocation is implied.

Defaults bound 262,144 membership INFOs, 8 MiB per strict record read and 24 MiB
aggregate max(stored, decoded) read work. That aggregate includes the condition
consumer's INFO reread. Each narrative read has a 65,536-field and 8,192-section
limit, with at most 8,192 prepared condition sites. A 64 MiB retained allowance
charges raw topic/INFO bodies plus compact metadata serialization, independently
of the membership index's same metadata allowance. These are scoped logical
budgets, not exact process heap or decoded UI/audio memory. Source handles,
caller-owned requests and script catalogues retain their existing separate limits.

Metadata serialization includes hashes and source structure rather than raw
subtitle/quest text or compiled bodies. Raw retail material remains local. The
source request producer alone does not establish a working original dialogue UI,
condition eligibility, source selection, speaker routing, voice playback, result
script timing or gameplay parity.
